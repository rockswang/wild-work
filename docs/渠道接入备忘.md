# 渠道接入备忘

> 本文件是 `AGENTS.md` 第 5 节的**详细正文**，从 `AGENTS.md` 拆出以降低常驻上下文占用。
> 内容为**各渠道的协议要点、凭据模型、已知限制与踩坑记录**。
> 新增渠道的通用步骤见本文开头「接入步骤」；各渠道专属细节见其后分节。
> 相关决议（R10/R16/R19/R44/R46/R57/R59/R65/R67/R69/R70 等）见 `docs/决议项.md`。

1. 新建 `internal/<channel>/` 包，实现 `provider.Upstream` 接口
2. `internal/auth` 增加对应 `Load<Channel>Dir()`（文件名前缀 `<channel>-*.json`；
   **glob 边界**：`qoder*.json` 会吞掉 `qodercn-`/`qodercom-` 前缀，LoadQoderDir 必须显式排除）
3. 装配处注册 `server.Runtime{Kind, Pool, Upstream, StaticModels}` + `app.Runtime{..., Scheduler}`
4. 前端渠道选择器加一项；`internal/login_<channel>` 实现登录编排（如需）
   > **无账号渠道（oczen）跳过第 2、4 步**：不建 auth 文件与加载器，虚拟账号由 `main` 装配时注入 pool，
   > 且 `app.reloadAccounts` 不得纳入（否则 `SyncToDir` 会把它剔除）。

> provider.Kind 即模型名前缀；server 按 `channel/<model>` 前缀路由，无需改接口。
> **QoderCN（`qodercn/*`）**：qoder2api 参数形态（cosyVersion 1.0.10、18 头含 cosy-scene 族、
> session_type=qoder、identity userType 实测回填）；签到仅 campaigns（legacy daily-check-in 已 DISABLED，
> 其 claim 恒返回 409 会造成假成功，故不再使用）；每日 10:00 开放 + 10:00–12:00 窗口内重试（见不变量 23）；
> 动态模型表（无静态兑底，上次成功缓存）。详见 `docs/qoderCN渠道接入备忘.md`。
> **QoderCOM（`qodercom/*`）**：国际版（qoder.com/openapi.qoder.sh/api1+api2.qoder.sh 三域分离）；
> 凭据与 CN 区完全隔离（双向 401）；签到仅 campaigns（无 daily-check-in，实测 404）；
> 每日 10:00 开放 + 10:00–12:00 窗口内重试（同 CN，见不变量 23）。详见 `docs/qoderCOM渠道抓包分析与接入计划.md`。
> **旧 Qoder（`qoder/*`，QoderWork）已从界面下线**：代码与路由保留，存量账号仍可用；不新增功能，后续可移除。
> **Qoder 双区签到的实际方式（2026-10-17 本机 Qoder 桌面端 0.4.8 取证）**：
> 签到就是桌面端的「活动（campaign）」子系统，与 legacy daily-check-in 无关 ——
> ① 发现 `GET {OpenAPIBase}/sash/api/v1/me/campaigns`（Bearer `dt-` + `cosy-clienttype:10`）；
> ② 领取 `POST .../campaigns/{campaignId}/claim`（空 body），依据是活动页前端源码
> （`g.alicdn.com/qbase/qoder/0.0.727/growth-page/activity-iframe/activity-iframe.js`）把
> `campaign:apiRequest` 的 `claimCampaign` 映射到该路径；③ 另有 `GET .../{id}/reward`（兑换码类活动用，本工具未接）。
> 桌面端另带 `cosy-version` 与整族 `cosy-machine*`（OS/Hostname/Id/Token/Code/Type）；**单发 A/B 实测
> （同凭据、同 GET、只差请求头，共 2 次）两回包逐字节相同** ⇒ 该头族不影响 campaigns 结果，本工具不复制。
> ⚠️ **已知边界**：每日 `CLAIM_BENEFIT` 活动按**客户端会话/设备**下发。同一 uid、相差 10 秒的同一端点上，
> 桌面端看到 `CLAIMABLE +100 CREDITS`，本工具回包只有 `VIEW_DETAILS/CLAIMED`（响应原文 1277 字节）。
> 故 QoderCOM 上的 `no_campaign` 可能是**上游如实未下发**、不是解析缺陷 —— 这正是
> `no_campaign` 文案必须带上游响应摘要的原因（见 `internal/qodercom/checkin.go` 头部注释）。
> `claimStatus` 线上形态是**扁平字符串**（三份 0.4.8 主进程日志逐字实证；`"claimStatus":{"status"` 全日志 0 命中），
> 对象形态只作防御性兼容。QoderCN 侧已实证真领到：`qodercn checkin campaigns … status=claimed amount=100 msg=签到成功 +100`。
> WorkBuddyAI 国际版：`DailyCheckin` 实现为「免费模型对话保活 + 签到探测」（对用户透明，无前端界面）；
> token 有效期 365 天，故 KeepaliveHours 设为 nil。详见 `docs/workbuddy国际版渠道接入备忘.md`。
> **MonkeyCode（`monkeycode/*`，平台托管模型）**：凭据由面板「从本机客户端导入」从官方客户端
> （ohmyagent）的 settings.json 取得，一个账号 = `oma_` api_key + `omas_` signing_secret；
> 按模型声明的 type 分流到 `{base}/messages`（Anthropic 形状）或 `{base}/responses`（Responses 形状），
> 两路都是无状态 SSE；上游无目录/额度/刷新接口 → 模型表静态、额度恒 0、`RefreshToken` 空实现。
> 协议对照参考：`codkeep/MonkeyCodeReverseEngineer`（Apache-2.0）。
> **小浣熊（`raccoon/*`）**：两条添加路径 —— 面板登录按钮走**网页版自动登录**（拉起独立 profile 的
> Edge/Chrome，登录后经 CDP 捕获 Cookie `xhx_token`，见 internal/login_raccoon/web.go；
> 跨平台，不再依赖 Windows 注册表，详见 R44），弹窗次按钮「从客户端导入」读本机
> `.box-agent/config/auth.json`。凭据 access_token ≈1h + refresh_token ≈30d，保活每 4 小时一次
> 以减少「请求先 401 再刷新」的往返。**签到走 `setting_info`**（每日积分的惰性落账触发点，
> 见 R65 与 internal/raccoon/checkin.go）。**注意互踢**：上游 refresh 轮换 refresh_token，
> 同账号凭据共用（本工具 + 浏览器/客户端）会互踢，需各自单独登录（独立 `sid`）才能并存。
> 上游默认档即最深思考，故不接档位面。
> 接口结构整理：`xxhhlk/raccoon2api`（MIT）。
> **Loomy（`loomy/*`）**：导入型渠道 —— 凭据由面板「从本机客户端导入」读
> `C:\Users\Public\Loomy\<hash>\userData\auth-session.json`。上游**无 refresh 端点**，
> session 约 14 天，到期需重新导入；故 `RefreshToken` 留空、定时任务全关（保活会被
> 按「无 refresh token」跳过，但每天仍空跑一次并记失败）。鉴权失败是 **HTTP 200 +
> 业务码 `100002`**（不是 401），业务码判定必须排在状态码判定之前。
> **积分口径**：`availableBalance` = 常规池 `balance`（长期有效）+ 每日池 `dailyBalance`
> （**当日有效** —— 上游只下发数值、不下发到期时间，按渠道规则静态补 `ExpireAt` = 今天，
> 面板据此把每日池算作临期额度）。
> 接口结构整理：`xxhhlk/loomy2api`（MIT）。
> **Cline（`cline/*`）**：**粘贴型渠道** —— 凭据是官方文档化的 `sk_` API Key
> （入口：`app.cline.bot` → 注册账号 → `Account / API Keys` → `Create API Key`，
> 形如 `sk_` + 64 hex，**只在创建时完整显示一次**；2026-10-12 用户订正，
> 旧记「Settings → API Keys」有误）。
> 一个 Cline 账号一把 Key；**Key 不过期、不轮换** ⇒ 无 `RefreshToken`、无保活、无签到，
> 也没有 R26/R44 那种「同凭据多处使用互踢」的问题（见 R46）。
> **模型面不做任何本地假设**（2026-10-12 简化）：绑死上游 `recommended-models` 的 `free[]`
> 原样透传——ID 保留 `cline-free/*` 别名不改写（用户后台观察：免费入口是别名条目，
> 厂商真实名会扣费；注意此为观察级证据，计价逐请求抽签）、无静态表、无本地配置、
> 不拉 `/api/v1/models`（458 条 OpenRouter 镜像）。本地校验集 = 暴露集 = `free[]`，
> 冷启动放行；上游抖动用已知集兑底。
> **两个必须遵守的实现约束**：① 出站必带**非空 `X-CLIENT-TYPE`**，否则 `cline-free/*` 全量 403
> 且**不报错**（值随意，缺失/空值才拒）；② `Classify` 必须从被压平成 500 的 body 里取**内层**状态码，
> 并把 `limit_rpd`/`Daily limit reached`/`temporarily rate-limited` 归成**模型级**处置
> （`ErrPassthrough` + 模型冷却），**绝不软化账号**（见 R47）。
> **`max_tokens`**：客户端未给则**不传**（不传最稳），<64 抬到 64、>200000 压到 200000
> ——实测 8 被上游拒、16 会造成 `empty response content`（推理吃光预算，流式同样中招）。
> 上游**无余额/额度端点** ⇒ `UserResource` 恒 0（**不得返回 error**），面板显示「不适用」，
> 实际花费来自逐请求 `usage.cost`。**不承诺价格**：`free` 前缀 / `is_byok` / `provider` 实测都不能
> 当免费判据（同前缀有扣费、非 free 后缀反倒 cost=0，且同 ID 相邻两笔会漂移）。
> 添加时只调 `GET /api/v1/api-keys` 验证（**零 token 消耗**），uid 取其 `apk-…` id；
> 官方配额字段名是 `…UsageCostUSDPerUser`（按**账号**计）⇒ 同账号多把 Key 共享一份额度，须告警。
> 依据与实测全表见 `docs/cline渠道接入计划.md` 与 `docs/cline2api线索项目评估.md`。

> **OpenCodeZen（`oczen/*`，匿名免费）**：凭证固定字面量 `public`，无账号/无签到/无积分；
> 免费档有四道闸门（`ses_<12hex><14Base62>` 会话头**且其 12 位 hex 时间戳段须为官方
> `Identifier.descending()` 编码**，见 R53b；`stream:true` 且 tools 含 `bash`/`read`；
> 伪装头齐套但**不得带 `x-opencode-request`**、且 `x-opencode-session`/`x-opencode-session-id` 须同值；
> **基址按凭证车道分流**（匿名 → `/inference/v1`，自备 `sk-…` key → `/zen/v1`），
> 见 R69），缺一即 403 FreeTierError；面板固定一项「[OpenCodeZen] 匿名」、积分显示「不适用」，
> 不可增删停用。详见 `docs/opencodezen渠道接入备忘.md`。
> **Kilo（`kilo/*`，免密免费池）**：上游 `https://api.kilo.ai/api/gateway`（OpenAI 兼容面），
> **不需要任何凭据**（无 `Authorization`、无指纹头）。免费范围**只认清单行的 `isFree: true`**：
> `GET /models` 是 OpenRouter 风格（`data[].id` / `isFree` / `context_length` / `supported_parameters`），
> **不按模型名猜**（那是 oczen 的口径，两边清单形状不同）。对话 `POST /chat/completions` 恒 `stream:true`；
> SSE 以 `data: [DONE]` 收尾，排队期间上游会下发 `: KILO PROCESSING` 注释行——解析器跳过即可，
> 且**不得**把它当作空闲超时的证据（它恰恰证明连接活着）。
> 无账号/无签到/无积分（面板显示「不适用」），与 oczen 同属无账号渠道（R16）：不建 auth 加载器、
> 不进 `reloadAccounts`，虚拟账号 `kilo-anonymous` 由 main 注入；`SingleAccount: true` ⇒
> 任何账号级惩罚都等于整条渠道下线，故错误一律原文透传。
> **未接备用上游通道**：本仓未观测到该网关的地区限制，按 R57「备用通道默认不参与任何请求」
> 不预先接上；若实测出现 403 地区文案，再按 R62 的 `backuplink.Replay` 编排补。
> 静态兜底只有一条 `kilo-auto/free`（唯一有公开出处的 id）；其它免费 id 一律动态拉取。
> **CodeArts（`codearts/*`，华为云 CodeArts Agent）**：对话走华为 **snap-access**，鉴权是 **SDK-HMAC-SHA256 签名**。
> ⚠️ 签名必须逐字节一致：参与签名的头名按**小写字典序**、URI **补尾 `/`**、query **去前导 `?`**、`x-sdk-date` 剥掉分隔符；
> **`maas_type` 必须参与签名**、**`Agent-Type` 必须不参与**（否则 `401 APIG.0301`）。签名向量已与 .NET 独立实现交叉比对。
> 凭据是 **AK/SK + SecurityToken**（落 `auth.Extra`；`AccessToken` 承载 AK 只是为了让 `auth.Parse`
> 的非空校验通过 —— ⚠️ **AK 不是稳定账号标识**，见下一条），续期走 **DPoP(ES256) + PKCE → STS**。
> ⚠️ **账号唯一标识（UID）—— 本渠道的已知限制**：上游 STS 只回 `credentials.*` + `refresh_token`，
> **不含任何身份字段**。2026-10-17 实测抓包证实：控制面 `statistics/plugin` 的响应字段全集里
> **没有** `user_id`/`user_name`/`domain_id`/`account`/`tenant`/`enterprise`（唯一含 `domain` 的地方也不是 JSON key）。
> 因此 UID 只能落到**每次新签发的临时 AK** ⇒ 直接用会导致「点一次新增就多一个账号」；而浏览器已登录
> 华为云时授权页会**秒过**（看不到输账号的过程），使该缺陷每次都触发。
> 处置 = **方案 B**（`login_codearts.SaveAuth`）：无稳定身份字段时，若该渠道已有账号则**复用其 UID**
> （覆盖同一文件）。守门测试见 `uid_reuse_test.go`。
> **多华为账号目前无法区分** —— 这是「上游不提供稳定身份」的客观限制，不是实现取舍；若将来发现可用的
> 身份端点，应按它改为方案 A。
> **额度计量单位**：控制面响应同时含 `is_credit_package`/`is_token_package` 与
> `package_credit_*`/`package_token_amount` ⇒ 本渠道**两种套餐并存**。实测账号是**积分套餐**
> （`codearts.agent.individual.trial` 体验版，6500 分）⇒ 按积分口径展示（`credits_unit` 留空）是**正确**的。
> ⚠️ 若某账号是 token 套餐，其单位本应随之切换 —— 渠道级 `credits_unit` 表达不了「同渠道不同套餐」，
> 记为**待观察项**（当前账号不受影响）。
> 错误面：`4291`（额度用尽，**不可重试** → `ErrHardCredit`）与 **独立数字 429**、`TM.00001041`、`81111`（排队 → `ErrSoftRate` 冷却换号）
> 必须分开判（用 `Contains("429")` 会误命中 `4291` ⇒ 表现为「30 分钟静默重试、零输出」）；
> 统一处理「**HTTP 200 + 流内 `error_code`**」。benefit 额度按 **UTC+8 自然日**重置（服务端不下发重置时刻，本地按次日 00:00 推算并标注「预计」）。
> 签到是**三步**（账户类型 → `USER_LOGIN` 活动 → claim），渠道包实现了 `CheckinReporter` + `CheckinGranter`。
> ⚠️ **SSE 归一**：上游帧是 `data:{...}`（**冒号后无空格**），而 `internal/upstream` 的解析只认 `data: `（带空格）——
> 不归一的话**每一帧**都会落进「注释行」分支、整条流被判成 `upstream_parse` 空流。本包在 `streamTap` 里统一补空格并有回归测试锁定。
> 这同时暴露 `internal/upstream` 对 SSE 规范（冒号后的空格是**可选**的）不够宽容，属**跨渠道潜在脆弱点**，已记入项目待改进项。
> 协议依据见本地只读分析 `docs/ref-ofm-渠道-codearts-opencode-kilo.md`（**逆向分析类文档不入库**）。
> **Gemini（`gemini/*`，Google Code Assist）**：推理 `POST {daily|sandbox}.cloudcode-pa.googleapis.com/v1internal:streamGenerateContent?alt=sse`
> （`quota` 与 `loadCodeAssist` **固定走 sandbox**）。
> 鉴权是 `Bearer` + **逐字身份五头**（`User-Agent: antigravity/4.3.0 (cmdc-pak)`、`x-client-name`、`x-client-version`、
> `x-machine-id: cmdc-pak`、`x-vscode-sessionid: proxy`）；**不得**带 `x-goog-api-key`，流式**刻意不带** `Accept`。
> ⚠️ 出站信封必须**逐层字母序序列化**：Go 的 `encoding/json` 对结构体按**字段声明序**输出，故把字段按字母序声明即可；
> **绝不能用 map**（遍历序随机 ⇒ 字节不一致）。工具 schema/args 走递归排序且**叶子字节不动**（`UseNumber` 防 float64 重写数字）。
> 模型 id 强制带档位后缀 `gemini-3.8-flash-<tier>`；SSE 是单行 `data:`（**无 event 名**）、以 `data: [DONE]` 收尾，
> 两种载荷（`{"response":{…}}` 与裸 Response）都要认。
> 额度是**配额窗口剩余百分比**（只认 `gemini-5h` / `gemini-weekly`），映射为 **`InfoOnly`** 的 `ResourceItem`
> （不参与积分算术、不进临期统计，避免「99% + 99% = 198」这类假积分）；`UserResource` 恒 0 ⇒ **不纳入**积分自动刷新。
> **无签到**（`DailyCheckin` 返回明确「不支持」错误，按 `noExplicitCheckin` 处理）。
> 登录：loopback OAuth（`localhost:<动态端口>/oauth-callback`、**双栈**、动态端口失败退 `8845`、
> `state=randomBytes(16).hex` **强制校验**、**无 PKCE**、换码**强制 `client_secret`**；client_id/secret 为内嵌公开常量）。
> ⚠️ 存疑项（勿当事实）：`sessionId` 的派生取值与原版**不逐字相同**（原版哈希未被反推出来，仅复刻依赖维度与确定性）；
> 流内 error 帧的确切形态未确认；`daily` 与 `sandbox` 的功能差异未确认。
> 协议依据见本地只读分析 `docs/ref-ofm-渠道-zcode-gemini.md`（**逆向分析类文档不入库**）。
> **ZCode（`zcode/*`，智谱）**：对话是 **Anthropic Messages** 形态（积分腿 `/api/v1/zcode-plan/anthropic/v1/messages`、
> 订阅腿 `api.z.ai/api/anthropic/v1/messages`），选腿由「模型白名单 + 凭据可用性」决定。
> 鉴权头族约 11 个（含 `X-Device-Mid`，缺则 400 + `3001`）；⚠️ 请求体顶层 `system` **必须内嵌官方身份块**
> （cliPrefix 42 + stable 2856 = 2898 字符，已用 sha256 逐字节锁定），否则 **405 + `3012`**；
> 本仓在**发请求前本地校验**身份块，失败按**请求级错误**返回（不罚号不轮换，避免本地缺陷冷却健康账号）。
